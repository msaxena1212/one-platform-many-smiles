## Receipt rule

Every financial transaction is considered complete only when the accounting event is `POSTED` and its corresponding financial receipt exists. The receipt is generated by the database trigger and linked 1:1 to the accounting event. Incoming, outgoing, PDC lifecycle, deposit, refund, adjustment and non-cash journal transactions are all covered.

### Final production rule

A financial receipt is never manually created, edited, or deleted. A financial transaction is posted through the Accounting Event / Atomic Posting pipeline, and the database generates exactly one authoritative receipt. Corrections use reversal/adjustment accounting events and therefore create their own audit evidence.
